# ShadowKV Reproduction — Progress Log

Running log of what we've done. Newest entries at the top.

## Goal

Replicate the ShadowKV paper (https://github.com/ByteDance-Seed/ShadowKV).
**Ultimate direction:** run it on modern models, specifically **GLM-4.x / "GLM 5.1"**.
**Current scope:** get the efficiency benchmark `test/e2e.py` running in Docker — nothing else.

## Key decisions

- **Base image:** `pytorch/pytorch:2.3.1-cuda12.1-cudnn8-devel`.
- **Kernel arch:** compile for `sm_90` (`TORCH_CUDA_ARCH_LIST=9.0`) — no GPU visible at build time.
- **`minference` fix (the "outdated requirements" issue):** upstream unpinned `minference` → 0.1.6.0,
  which bumps torch/transformers. We pin **`minference==0.1.5.post1`** and install `--no-deps`.
- **Kept** `vllm==0.5.3.post1` (imported at module load by `models/llama.py` / `models/glm.py`).
- **Dropped** `nemo_toolkit==1.23` and `numpy==1.23.2` (only needed to BUILD RULER). Instead we
  synthesize a dummy `qa_2` dataset for throughput-only measurement.
- **Models:** mounted from an offline HF cache at runtime (`TRANSFORMERS_OFFLINE=1`).

## Build fixes applied during the build

The internal Nexus pip mirror + old vllm pin + the Hopper GPU surfaced several issues, all fixed in
`docker/requirements-e2e.txt` / `Dockerfile`:
1. **Large-wheel read timeouts** (vllm is a 158 MB wheel): added
   `PIP_DEFAULT_TIMEOUT=300` + `PIP_RETRIES=10` to the Dockerfile ENV.
2. **`openai` 404 on mirror**: vllm 0.5.3.post1 left `openai` unpinned → resolver picked
   2.50.0 (wheel not mirrored, API-incompatible). Pinned `openai==1.40.0`.
3. **`fastapi`/`annotated-doc` 404**: newest fastapi pulls `annotated-doc` (not mirrored).
   Pinned `fastapi==0.112.2` (vllm-0.5.3 era).
4. **flashinfer dragged in `torch==2.3`**: the `flashinfer-0.2.0.post1` wheel pins `torch==2.3`
   (i.e. 2.3.0), which would downgrade the base torch 2.3.1 and pull a fresh multi-GB torch +
   nvidia CUDA pip stack. Installed flashinfer with `--no-deps` (torch 2.3.1 is ABI-compatible).
5. **`libc10.so` ImportError in the build-time smoke test**: `from kernels import shadowkv` was run
   without `import torch` first, so torch's `libc10.so` wasn't loaded. Fixed the smoke test to
   `import torch` first and added torch's lib dir to `LD_LIBRARY_PATH`.
6. **Hopper cuBLASLt SIGFPE during decode** (the big one): torch 2.3.1 bundles CUDA 12.1 cuBLAS,
   whose cuBLASLt has a known **floating-point exception on sm_90 for small-M GEMMs**. Prefill
   (large M) worked, but the first decode step — the qkv `F.linear` with M = batch (q_len=1) —
   crashed with `Floating point exception (core dumped)` inside `cublasLtTSTMatmulAlgoGetHeuristic`
   (confirmed via gdb backtrace + a minimal bf16 M=1 `F.linear` repro, exit 136). Fixed by
   installing `nvidia-cublas-cu12==12.6.4.1` and `LD_PRELOAD`-ing its `libcublasLt.so.12` +
   `libcublas.so.12` over torch's bundled 12.1 libs (RPATH otherwise beats `LD_LIBRARY_PATH`).
   Host driver is CUDA 12.9, so the newer cuBLAS is safe.

## GPU passthrough note

`--gpus all` alone gave `Failed to initialize NVML: Unknown Error` / `torch.cuda.is_available()=False`
on this host; adding **`--privileged`** fixes it (matches the user's `docker run` template). Because
`--privileged` exposes ALL 8 GPUs regardless of `--gpus device=`, `run_e2e.sh` pins the device with
`CUDA_VISIBLE_DEVICES=$GPU` (default GPU 4; e2e.py hardcodes `cuda:0`). GPUs 4/5/6 were free.
